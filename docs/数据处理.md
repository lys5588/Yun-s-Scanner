# 数据处理

## 目的与输入输出

将普通手机视频转换为可追溯的训练图片、真实估计的相机和初始化点云。普通视频可走 Mac 页面或 iPhone 首页的“使用已有视频”。手机入口从照片或文件选择并在设备内完成处理，历史页另保留模型 ZIP 导入；App 内直接拍摄是另一条输入链路，拍摄前可选仅相机或相机 + LiDAR。直接拍摄的仅相机模式仍保留真实 ARKit 位姿，和需要重新估计所有相机的普通视频导入不同。

Mac 视频入口支持 MOV、MP4、M4V，要求 SDR、时长不超过 180 秒；检测到 PQ/HLG HDR 时拒绝处理。页面上传上限为 2 GB。每隔至少 0.5 秒选择一个原始解码帧，按比例缩小至长边不超过 1600 像素，不插帧或复制帧，至少需要 8 帧。

每次运行的数据位于 `local-data/runs/<实验编号>/scan/`：

| 文件 | 内容与用途 |
| --- | --- |
| `video-source.json` | 源文件名、SHA-256、ffprobe 探测信息、时间戳策略；明确没有 ARKit 位姿和 LiDAR 深度 |
| `images/frame_*.jpg` | 抽取并缩放后的图像，后续摄影测量和训练共用 |
| `video-frames.json` | `imageFile: String` 与 `timestamp: Double` 的有序数组；时间单位为秒 |
| `photogrammetry-poses.json` | 摄影测量返回的原始样本 ID、图像、时间、平移、四元数、列主序矩阵和可选内参 |
| `photogrammetry-points.ply` | 摄影测量的原始有色稀疏点云 |
| `poses.jsonl` | 每行一条兼容 `FrameRecord` 的训练记录，含图像名、源时间、行主序 c2w 和逐帧内参 |
| `points.ply` | 归一化后的有色初始化点云，不是高斯模型 |
| `video-import.json` | 相机约定选择、投影检查、归一化中心与尺度、有效/丢弃帧及原因、任意尺度声明 |

## 实现入口与约定

任务、上传、抽帧和状态管理由 `tools/mac_demo.py` 实现；`tools/prepare_video_scan.swift` 通过 `RealityKit.PhotogrammetrySession` 的 `.poses`、`.pointCloud` 请求获取实际结果；`Training/TrainingDataset.swift` 消费训练记录和点云，App 源码路径均以 `arkit-3dgs-scanner/` 为前缀。

手机入口由 `VideoImport/VideoImportView.swift`、`VideoImportCoordinator.swift`、`VideoFrameExtractor.swift`、`VideoPhotogrammetry.swift` 实现。使用 iOS 26+ 的实际 `PhotogrammetrySession.isSupported` 与设备输入上限，最多 200 帧、长边 1600、180 秒及 2 GB；不支持时允许预览但禁用准备按钮。抽帧通过压缩 sample 的 `CMSampleBufferGetOutputPresentationTimeStamp` 保留容器 edit-list 后的真实时间，精确取帧并核对 actualTime；应用一次 preferredTransform，通过 `forceSDR` 和 sRGB 色彩管理输出 8-bit JPEG，避免仅修改 HDR 标签。`video-frames.json` 还记录有理数时间、实际图像尺寸；`video-source.json` 保留 SHA-256、原始颜色、方向和处理方式。

`VideoPhotogrammetry` 用真实 `.poses` / `.pointCloud` 结果沿用下述几何契约；原始 lensDistortionData 保存在 raw poses 中，当前训练仍使用针孔近似，不声称已经做额外畸变校正。照片和文件源只读，App 处理私有副本。暂存阶段不出现在历史；取消需等待 RealityKit 结束，再删除本次暂存输出。最终 manifest 和概要完整后原子移动至扫描库，失败保留用户源视频。

**后台处理。** 准备任务由前台操作启动并申请持续后台时间。视频摄影测量使用 GPU，因此除了 iOS 26+ 接口，还必须同时通过设备后台 GPU 能力、签名 entitlement 和实际 `BGContinuedProcessingTask` grant 检查；仅提交请求不放行后台计算。未获准时切后台会安全停止当前准备，回前台可重新开始，原片不变；用户取消、系统到期、严重过热或内存警告仍可停止任务。抽帧/摄影测量没有断点恢复，不能承诺从停止的百分比续算。系统取消即使在前台也响应，强制结束 App 后不会继续。

build 8 将视频处理页的未获准提示明确为“正在前台处理，请保持 App 打开，完成后再切换”，避免将后台资源限制误认为前台计算启动失败。`VideoImportView` 只在实际 `.background` 时调用 `sceneDidEnterBackground()`；控制中心等引起的 `.inactive` 不再直接取消任务。真正切后台且无 grant 时仍取消并等待工作线程退出，保留所选原视频以便重新开始。系统到期、内存与温度保护保持有效；本改动没有增加后台 GPU 签名权限。诊断新增 `videoForegroundInactive` 和 `videoStoppedOnBackground`，用于区分短暂失焦与真实后台停止。

直接拍摄结束后的位姿优化和点云计算使用 CPU 持续后台申请，独立于视频摄影测量的 GPU 能力；实际授权不足同样走停止与数据保护。实时相机/ARKit 采集本身仍必须前台运行。共享生命周期入口为 `Background/ContinuedProcessingLease.swift`，任务结束前等待工作线程退出，避免双重执行或半成品发布。

当前 Personal Team 的 Background GPU Access 签名申请已被 Xcode 拒绝，因此默认个人版本仍需前台执行视频摄影测量，不能交付持续 GPU 后台准备。可选完整权限配置为 `Config/BackgroundGPU.entitlements`；具备签名权限后仍需实际设备能力与任务 grant，不能把此文件存在当作可运行证据。后台能力及任务事件在 `Documents/background-processing.json` 记录。

**时间戳。** 抽帧使用 FFmpeg `-copyts`、`-fps_mode passthrough` 和 `-avoid_negative_ts disabled`，保留解码后的源 PTS，不自动归零。起点可以非零或为负；时间必须有限且严格递增，图像数必须与时间戳数相等。这里的 PTS 是源视频的呈现时间，不是 ARFrame 系统启动时间，也不是拍摄的墙上时钟时间。

**相机与尺度。** 只有存在有效估计内参和位姿的帧才能进入训练，至少保留 8 帧，且图像分辨率必须一致。工具比较“返回矩阵直接作为 GL 风格 c2w”和“翻转局部 Y/Z 轴后作为 GL 风格 c2w”两种解释，通过点云的正深度和图像内投影计数选择；证据不足即失败，不补造相机。

归一化以原始点云均值为中心，以点到中心距离的第 95 百分位数的倒数为缩放因子；点云和相机平移应用相同变换，旋转与图像内参保持对应。`video-import.json` 写入 `metricScale: false` 和 `unit: arbitrary_photogrammetry_unit_normalized`，结果不能解释为米制。原始摄影测量结果另存，归一化不覆盖它们。

训练记录使用 GL/ARKit 相机轴约定（朝 −Z、Y 向上），不意味着该视频由 ARKit 采集。内参对应最终保存的 JPEG 像素。普通视频没有深度文件；曝光和 ISO 的零值仅为旧记录结构的兼容占位，清单明确标注未知，不能用于声称测得曝光或图像质量。Mac 训练入口关闭深度初始化、深度损失和再次位姿精修。

ARKit 采集路径的 RGB、内参、位姿和深度需关联同一帧，深度保留其原始分辨率与米制语义；普通视频不生成这些传感器数据。后续 COLMAP 导出由 `Capture/ExportManager.swift` 负责 GL c2w 到 OpenCV w2c 的转换；启用世界 Y/Z 翻转时同步变换位姿和点云，不能在输入侧重复翻转。训练或优化后的位姿另存，不覆盖原始采集记录。视频历史不提供 ARKit 米制优化和公尺量测，已旋正的 JPEG 预览不再按重力旋转。普通视频归档时 `points.ply` 保留任意单位；`training-coordinate-frame.json` 记录 `metricScale`、`unit`、`inputGravityAlignment`、`inputWorldToCOLMAPRowMajor` 和 `worldRotationMeaning`，明确 COLMAP 的可选世界旋转只是导出约定，不是重力或尺度校准。无效视频清单在覆盖旧输出前失败。

**失败语义。** 抽帧不足、时间不合法、摄影测量缺失结果、非有限坐标、无效内参、分辨率不一致或相机约定不明确都会中止任务。日志保留在实验目录的 `run.log`。`video-import.json` 在训练输入准备完毕后写出；任务失败或取消不标为完成。准备完成但训练工具不可用时标为 `ready_for_training`，不代表已生成模型。

## 验证方法

```sh
python3 tools/test_mac_demo.py
.build/mac-demo/prepare_video_scan --self-test
python3 tools/check_project.py
```

Python 回归覆盖上传接口、路径与参数、任务失败/取消/重启状态、恢复前置文件、构建指纹、FFmpeg 抽帧及源时间戳。非零起始时间使用实际编码的 MOV，与 ffprobe 解码时间对照；负 PTS 回归使用模拟解码输出，避免 MOV 编辑列表裁掉负时间前导帧造成误判。helper 自测检查带符号时间轴、非法时间拒绝、相机约定选择、歧义拒绝、投影归一化不变性和 PLY 字节格式。

真实视频到位后，还需核对源摘要、抽帧画面及时间、有效/丢弃帧、原始与归一化相机/点云，以及实际训练结果的几何、朝向和颜色。自测不能替代这些检查。
