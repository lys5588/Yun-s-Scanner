# 模型查看

## 1. 目的与输入输出

查看已完成的真实高斯模型，支持旋转、平移、缩放、重置和重新打开。初始化点云 `points.ply` 不能作为高斯模型交付。

- Mac 页面读取 `scan/gaussian-training/model/gaussians.ply`，通过固定版本 SuperSplat Viewer 显示；任务完成后可下载 `model.zip`。
- iPhone 从“扫描记录 → 导入 3DGS 模型”接收 ZIP。包内必须有 `gaussians.sog` 或标准 GS `gaussians.ply`、有效的 `gaussians.json`，以及至少一个可用视角的 `training-poses.jsonl`。同时存在 SOG 和 PLY 时优先 SOG。
- 模型附带的 `video-import.json`、实验记录和可选 PPISP、预览图保留在模型目录。导入目录另写 `imported-model.json`，表示接收既有模型；不生成手机采集或本机训练成功记录。没有原始照片时不提供继续训练。

完成模型后点击“分享 3DGS 模型”，先选 **SOG（压缩模型）**或 **PLY（标准 3DGS）**，再进入系统分享。SOG 通常体积更小，PLY 适合兼容标准 3DGS PLY 的外部工具；具体大小取决于模型。两者均以 ZIP 包装，保留本 App 重新导入所需的相机和元数据。

## 2. 实现入口与约定

| 入口 | 职责 |
| --- | --- |
| `tools/mac_demo.py`、`tools/mac_demo_web/` | 完成状态、浏览器模型地址、ZIP 导出与 Viewer 配置 |
| `History/GaussianModelImport.swift`、`History/ScanLibrary.swift` | 归档校验、导入暂存和原子发布 |
| `Config/Info.plist`（项目根目录）、`History/ScanHistoryView.swift` | Files 文件共享入口、导入模型卡片与预览封面 |
| `Training/GaussianExport.swift`、`Training/GaussianSOG.swift` | PLY/SOG 参数、坐标转换、纹理解码 |
| `Training/TrainingWorkspace.swift`、`Training/UI/GaussianTrainingView.swift` | 显式选择分享格式、原子打包与缺失格式提示 |
| `Training/GaussianModelViewer.swift` | 加载、初始视角、内存检查和后端记录 |
| `Training/GaussianRealityKitViewer.swift`、`Training/GaussianRenderer.swift`、`Training/UI/GaussianTrainingView.swift` | 原生资源、共享相机、手势和 Metal 回退 |

除另行注明外，表中 App 路径相对 `arkit-3dgs-scanner/`。

**Mac 后端。** SuperSplat 固定提交为 `5976646dc972e7700fbde3948465795cca0a4ebc`，页面以 WebGL 加载标准 GS PLY。`viewer-settings.json` 关闭额外调色、锐化、泛光等后处理，当前使用 Viewer 默认取景。浏览器读取的是原始高斯颜色，不应用手机 PPISP 相机校正。

**ZIP 与错误语义。** 导入限制为压缩文件最多 512 MiB、解压内容最多 768 MiB、最多 64 个条目；检查 CRC、路径和已识别文件名冲突。元数据的高斯数量与 SH 阶数必须与选定模型一致。标准 PLY 检查完整行数据与有限数值；SOG 检查嵌套容器、元数据和引用纹理。全部验证后才将暂存目录移入历史记录；失败或取消不发布半成品。SOG 结构通过不代表纹理解码或 GPU 显示成功，查看失败时保留模型并报告错误。

**分享契约。** SOG 生成 `扫描名-3dgs-sog.zip`，PLY 生成 `扫描名-3dgs-ply.zip`；每包只包含所选 `gaussians.sog` 或 `gaussians.ply`，包内 `gaussians.json.format` 分别为 `3dgs-sog` 或 `3dgs-ply`。其他元数据字段保留，原模型目录不改；`training-poses.jsonl`、`video-import.json`、PPISP、实验和训练报告按已有内容随包保存。实验中的 outputs 仍记录原训练的全部输出，不伪装为重新训练或重新量化。每次分享重新打包当前模型，失败不替换上一份有效 ZIP；删除模型或整笔扫描也清理两种格式及旧版归档。

正常完成的新训练保存两种格式，因此两项均可选择。只有 SOG 的导入模型禁用 PLY 并说明原始 PLY 不存在；只有 PLY 的模型同样禁用 SOG。底层请求缺失格式也会报错，不会把另一格式改名或静默替换选择。ZIP 内的标准 GS PLY 是完整高斯参数模型，与扫描目录中的初始化 `points.ply` 不同。

**Files 与封面。** `Config/Info.plist` 显式设置 `UIFileSharingEnabled=true`，使 App 的 Documents 可从 Files 访问；本机验证发现仅有原构建设置时，最终 plist 缺少此项。导入模型没有采集照片时，历史卡片回退到已存在的 `gaussian-training/model/preview.jpg`，并按 `.up` 显示，避免套用采集姿态的旋转推断。缺少预览图时保留占位，预览图不计入采集帧数。

**iOS 后端。** 编译器 Swift 6.4 及以上、iOS 27 SDK、非模拟器构建中才包含原生分支，并在运行时检查 iOS 27。原生路径从参数缓冲区构造 `GaussianSplatResource` 与 `GaussianSplatComponent`，不假定 RealityKit 能直接打开 SOG/PLY。不可用、资源创建失败或内存不足时使用 Metal；PPISP 相机模式也选择 Metal。实际选择及原因写入模型目录的 `viewer-backend.txt`。

**坐标和颜色。** 内部模型与相机使用同一世界坐标。导出 PLY/SOG 时绕 X 轴旋转 180°，读回时逆变换，位置、四元数和 SH 符号保持一致。普通视频保留 `video-import.json` 声明的归一化任意尺度，不改称米制。四元数为 wxyz，尺度为对数，不透明度为 logits；原生资源分别使用指数和 sigmoid 激活，SH 按 RGB 元组排列，颜色空间设为 sRGB。PPISP 校正后的颜色与原始高斯颜色需要分别比较。

**相机与内存。** 导入模型的初始相机来自包内 `training-poses.jsonl`。RealityKit 与 Metal 共用父视图的 `OrbitCamera`：相同视场角、观察位置与交互状态，菜单和双击重置均恢复同一初始视图。原生相机仅将 OpenCV 的 +Y 向下、+Z 向前转换为 RealityKit 的 +Y 向上、朝 −Z，模型不再绕包围盒重定位。`OrbitCamera` 保持水平线，不承诺逐像素还原原照片的滚转和主点偏移。

模型加载前估算 Metal 内存；Metal 资源分配后再检查原生缓冲区，只将新增缓冲区与 450 MiB 预留空间同当前剩余可用内存比较，避免重复计算已分配的 Metal 资源。

## 3. 验证方法

- `bash tools/test_gaussian_reality_viewer.sh`：检查四元数规范化、无效值拒绝、相机轴转换、非原点相机位置与投影、原生缓冲区内存判断。
- `bash tools/verify_project.sh source`：包含模型导入与 Viewer 数学回归。原生 API 编译结果另以 iOS 真机目标和模拟器目标构建日志为准。
- 对同一真实模型分别检查浏览器与手机：可加载、朝向和基本颜色正确，旋转/平移/缩放正常，重置后视角一致，关闭后能重新打开。手机核对 `viewer-backend.txt`，分别记录原生、Metal 与 PPISP 的实际表现。
- 分别分享 SOG 和 PLY，检查包内只含所选模型、元数据格式与模型匹配、相机和非米制来源保留；重新导入两种包，检查只有单一格式的导入模型明确拒绝另一格式，并核对原模型未被修改。
- 导入损坏 ZIP、截断 PLY、无有效初始相机的模型应失败；结构合法的 SOG 仍须在手机验证纹理解码与 GPU 显示。
- 模拟器使用独立 XCUITest 实际选择 Files 中的真实模型 ZIP，再检查历史卡片、模型显示、拖转、双指缩放、重置和终止 App 后重开；结合截图与模型目录的 `viewer-backend.txt` 判定结果，不能仅凭测试返回成功推断后端或画质。

## 4. 实际结果与限制

2026-10-22：固定版本 SuperSplat Viewer 已构建；共享相机及内存判断修复后的 8 项数学回归通过。Xcode 27.1 / iOS 27.1 SDK 的 iPhoneOS 和 iPhoneSimulator 无签名完整构建均通过，真机目标包含原生 GaussianSplat 分支。

2026-10-23 已有真实视频重建模型，位于 `local-data/runs/20261023-002145-0965a5f9/scan/gaussian-training/model/`。SOG 与 PLY 已分别由共享解码器读取并在 Mac Metal 上渲染全部 12 个原始验证相机，零新增训练迭代、无相机对齐。图片对照的主要物体位置、方向及基础颜色一致；文字、线缆和椅子区域仍有模糊和局部缺损。SOG 的验证 PSNR 相比 PLY 下降约 0.255 dB。`model-qa/comparison_*.png` 从左到右为 SDR 输入、PLY 重载、SOG 重载；Mac 的 SOG 纹理解码/GPU 成功仍不能代替手机后端验证。

Mac 导出端点生成约 49.7 MB 的 `model.zip`，ZIP CRC 检查通过，包含 8 个模型及来源文件。真实包随后通过 App 共用的 `ScanLibrary.importGaussianModelArchive` 导入逻辑，并由全新进程重新打开历史库；99 个初始相机的顺序、位姿和完整内参不变，8 个文件逐字节一致，优先选择 SOG，任意尺度声明正确。导入记录没有伪造采集帧、LiDAR 或本地训练/检查点状态。临时验收工具及构建日志在 `.build/real-model-validation/`，真实运行日志为实验目录的 `import-validation-fixed.log`。

2026-10-23 在 iOS 27.0 的 iPhone 18 Pro 模拟器中，真实 Files ZIP 选择与导入通过；随后拖转、双指缩放、菜单重置、终止 App 后从历史记录重新打开通过。两个独立 UI 用例各执行 1 次、零失败，证据为 `.build/simulator-ui-validation/ImportFixed.xcresult`、`import-fixed.log`、`Viewer.xcresult` 和 `viewer.log`。`08-viewer-current.png` 可见桌面、显示器和笔记本的实际重建画面，仍有模糊及缺损。该轮同时修复 Files 文件共享开关和导入卡片封面；修复后的 iPhoneOS/iPhoneSimulator 构建均通过，日志为同目录 `ios-import-cover-fix.log`。

从当前模拟器 App 容器读取的 `viewer-backend.txt` 为 `backend=metal`；原因原文为 `PPISP correction requires the Metal renderer. Native status: This build does not include the iOS 27 RealityKit Gaussian splat API.` 该记录确认此次使用 Metal，模拟器构建不含原生分支；原因中的 PPISP 文案不代表本模型训练时启用了 PPISP，本轮 Mac 模型实际关闭该选项。

2026-10-23 显式 SOG/PLY 分享的 CPU 回归通过，使用真实 ZIP 编解码与共用导入实现检查两种格式、单格式导入限制、元数据及来源保留、失败保留旧包和删除清理。日志为 `.build/feature-reconstruction-20261023/share-test.log`；本轮手机系统分享界面及两格式在真机的显示仍需验收。

模拟器结果覆盖既有真实模型的 Files 导入、Metal 显示及上述交互，不覆盖实体 iPhone、原生 RealityKit、手机直接导入 MOV 重建或手机训练。浏览器拖转、缩放和自由视角仍未验收；模型画质和真机后端还需分别检查。

已有视频入口在系统选片后显示原片名称、时长、大小及播放预览。预览封面由 AVAssetImageGenerator.forceSDR 生成，点击播放使用系统播放器读取原片；处理图像由抽帧器独立生成 sRGB JPEG，均不修改源文件。模拟器原片 HDR 播放出现过高光截断，因此默认显示 SDR 封面；手机原片播放的 HDR 显示仍需真机核对。视频扫描的 JPEG 已应用方向变换，历史封面与回放固定按 up 显示，不使用 ARKit 重力再次旋转；该回归随模型导入 CPU 检查验证。模拟器实际不支持摄影测量时，重建按钮禁用并给出真机要求，选片预览仍可用。
